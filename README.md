# Neowise — помощник для входящих заявок

Менеджер вводит заявку, получает тему и черновик, проверяет текст и самостоятельно отправляет ответ клиенту. Учебные данные, внешних AI-сервисов нет.

## Запуск

Нужен Node.js 20.11+ (проверено на Node.js 24.22.3). Устанавливать зависимости и настраивать ключи не требуется.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт задаётся переменной окружения `PORT`.

## Тесты

В отдельном терминале из корня проекта:

```sh
node --test
```

Тесты сами поднимают сервер на свободном локальном порту и закрывают его. Используются только встроенные модули Node.js. Проверяются HTTP-контракт, все пять сбоев реального имитатора, схема AI, точная граница 300 мс виртуальными часами, отмена запроса, очистка старого черновика, ошибки сети и JSON, предел ожидания браузера и обратный порядок ответов. Тесты интерфейса вызывают настоящий обработчик формы через минимальный DOM-адаптер.

Ручная проверка: введите «Когда доставка?» — появятся тема и черновик. Затем последовательно отправьте `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`. Каждый раз должны появиться сообщение о ручном разборе и пустые тема/черновик. Пробелы дают подсказку «Введите текст заявки» без HTTP-запроса.

## Контракт API

`POST /api/triage`, JSON с полем `text`:

| Ситуация | HTTP | Ответ |
| --- | --- | --- |
| Битый JSON, отсутствующее поле, нестроковый или пустой после trim ввод | 400 | `{"status":"invalid_input"}` |
| Корректный AI-ответ | 200 | `{"status":"ready","topic":"delivery","draft":"…"}` |
| Таймаут, исключение, битый JSON AI, неизвестная тема, пустой/нестроковый черновик | 200 | `{"status":"manual_review","topic":null,"draft":null}` |

В `triage()` в `server.mjs` проверяются JSON модели, тема (`delivery`, `pricing`, `other`) и непустая строка черновика. В ответ копируются только разрешённые поля; пробелы по краям убираются. Ограничение ожидания модели — 300 мс, затем AbortSignal отменяет работу. Promise.race ограничивает ожидание и при игнорировании отмены асинхронным провайдером. Таймер очищается во всех случаях. `mock-ai.mjs` оставлен без изменений.

Интерфейс очищает предыдущий результат сразу при отправке. При сбое API, сети, HTTP или JSON показывает ручной разбор, не сохраняя чужой/старый черновик. Зависший сетевой запрос ограничен 5 секундами. Новый запрос отменяет предыдущий; счётчик запросов не даёт запоздавшему успеху или ошибке заменить свежий результат. Вывод через textContent не исполняет HTML модели.

## Польза и проверка

Менеджер получает заготовку ответа при успехе и явный переход к ручной работе при сбое, без риска принять старый черновик за результат новой заявки. Пользу можно измерить медианой времени от открытия заявки до проверенного ответа и долей заявок, обработанных без ручного написания с нуля; отдельно учитывать долю ручного разбора.

## Использование AI и границы

Использован ChatGPT/Codex для анализа, реализации и тестов. Фактически выполнены `node --test` и `git diff --check`; имитатор сравнен с исходным коммитом. В браузере также проверены успешный разбор «Когда доставка?» и последующий [timeout]: показан ручной разбор, прежние тема и черновик очищены.

Это учебный локальный сервер: нет авторизации, хранения заявок, отправки ответов и ограничений размера входящего тела. Таймаут ограничивает асинхронное ожидание, но не способен прервать синхронную блокировку event loop. Для реального AI нужен адаптер провайдера с поддержкой AbortSignal. Начальный код сохранён первым коммитом в main, исправления — в отдельной ветке.
